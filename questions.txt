(1) This program uses UDP, so messages are not guaranteed to arrive. If a message from a client to the server is dropped, the server will not process that move and the client may wait for a response that never comes. If a message from the server to a client is dropped, the server may update the game successfully, but the client may continue displaying an older board and wait indefinitely for an update.

(2) The save and load design is simple and has limitations. If the server crashes while the save file is being written, the file could be incomplete or corrupted. There is no backup, checksum, transaction mechanism, or version checking. Saving raw C structures can also depend on the platform and structure layout. Stored client network addresses may also become stale if clients disconnect or reconnect differently.
